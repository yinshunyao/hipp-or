# 测试范围

hipp-web `/wallet` 页面与 hipp-api `/wallet/*` 透传；依赖已配置 `HIPP_MANAGER_BASE` 且用户已通过 manager 登录拿到令牌。自动化：本次不编写。

# 测试用例

| 编号 | 前置条件 | 操作步骤 | 预期结果 | 自动化 |
|:---|:---|:---|:---|:---|
| WLT-01 | 已登录 | 资料层点「账户余额」 | 进入 `/wallet`，资料层收起 | 否 |
| WLT-02 | manager 有余额 | 打开账户页 | 展示正确余额 | 否 |
| WLT-03 | 已启用微信或支付宝 | 选渠道与面额，点充值 | 弹出对应标题的支付 Modal，内有二维码；正文无内嵌码 | 否 |
| WLT-04 | 弹窗打开且用户完成支付 | 等待轮询 | 提示成功，弹窗关闭，余额增加 | 否 |
| WLT-05 | 有历史充值 | 查看充值订单 | 列表含 pending/paid 等状态与金额 | 否 |
| WLT-06 | 有多产品流水 | 查看交易流水 | 仅 `product=or` 行；表头无「产品」列，有「标题」；会话消费行标题为对应会话名 | 否 |
| WLT-07 | 宽屏桌面 | 查看充值区宽度 | 内容列约 ≤480px，右侧留白 | 否 |
| WLT-08 | 未配置 manager 或令牌失效 | 打开账户页 | 提示重新登录或同步账户，不展示伪造余额 | 否 |
| WLT-09 | 余额充足、费率>0 | 在需求或商业场景完整咨询至话题结束 | 结束瞬间余额减少，流水含 consume_session；两场景规则相同 | 否 |
| WLT-10 | 余额不足 | 打开发消息前：进入需求页建会话，或点「新会话」 | 在出现输入框可写长文之前即 `code=46005` 并进入 `/wallet`；不新建会话（或空草稿不可用） | 否 |
| WLT-10a | 余额不足 | 已在会话中发消息 | 拒绝发送；响应/WS `code=46005`；助手气泡为余额不足文案；Web 可进 `/wallet`；不落库用户消息 | 否 |
| WLT-10b | manager 余额查询失败或未绑手机 | 建会话或发消息 | `code=46006`；展示校验失败/绑手机文案；不因 46005 误跳充值页 | 否 |
| WLT-11 | 话题已结束且 fee_charged=0 | 打开该会话详情 | 尝试补扣；成功则流水更新 | 否 |
| WLT-12 | 话题进行中 | 点「新会话」/空草稿 | 不扣费 | 否 |
