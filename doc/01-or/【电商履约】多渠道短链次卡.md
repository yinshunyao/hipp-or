# 背景

需求分析要在小红书、淘宝等渠道按次售卖：买家付款后拿到**每单独特短链**，免登录完成一次需求分析。现有能力是登录钱包扣费、小程序游客免费体验、结束后只读分享，无法支撑电商履约。

# 目标

1. 提供与渠道解耦的「1 次需求分析」短链权益，买家打开即可咨询。
2. 支持管理台手工造单验链路，以及小红书订单回调生成短链并回写发货。
3. 其它电商平台仅增加渠道适配，不改核销与会话核心。
4. 在 or 管理端单独维护电商渠道订单流水，状态可运营核对；真实资金仍在小红书千帆等渠道侧。

# 要求

## 功能性要求

1. 一单一 token 短链；状态含未绑定、已绑定、已用尽、已作废、已过期。
2. 打开短链可换临时登录态，进入需求分析场景完成**至多 1 次**话题（以话题结束计）。进行中交互页与分享页类似：无「新会话 / 归档 / 分享」菜单；完成后**同一短链自动只读**，可直接转发给他人查看，无需再点分享/归档。
3. 次卡会话不扣共享钱包；与登录用户 `consume_session` 并行不冲突。
4. 同一渠道外部订单号幂等，只对应一条有效短链。
5. 管理端「电商渠道订单」流水：状态仅 **已支付 / 已核销 / 已退费**。付款落单为已支付；用户完成本次咨询（话题结束）为已核销；管理端可点退费→短链失效不可再用。真实退款在千帆操作，本系统不记账本资金。
6. 管理台可生成短链/查单；支持管理员**线下出链**（手动生成 1 次需求分析短链，落「已支付」订单，等同线下收款后交付链接）；小红书接收开放平台订单消息生成短链并回写发货（密钥走环境变量）。
7. 管理端列表短链须为 https；状态/渠道等枚举中文展示；未消费短链支持复制链接与退费作废。

## 非功能性要求

1. 短链不可枚举（足够熵的随机 token）。
2. 密钥与 AppSecret 不进仓库明文。
3. 不做：阿奇索预导码主路径、用分享只读链当商品、复用 `mp_guest` 免费配额；不做站内对渠道货款的二次扣款/入账。
