# 背景

用户目前只能在微信小程序（`hipp-uni`）里完成登录、话题归档、需求咨询、商业咨询和人工客服会话。同一套后端接口（`/auth`、`/mp/chat`、当前用户资料）已经可用，但浏览器里没有对应的用户端，无法在桌面完成同样的咨询与会话整理。

# 目标

1. 提供可在浏览器使用的用户端，覆盖小程序已有的登录、话题列表、单会话对话、需求场景、商业场景与「我的」资料能力。
2. 让已登录用户用与小程序相同的后端会话与消息接口继续咨询，并看到归档话题、置顶、改名、删除和话题结束后的新话题。
3. 在宽屏上呈现适合阅读和连续对话的版式，同时在窄屏下仍能完成上述操作。

# 要求

## 功能性要求

- 工程位于 `hipp-or/hipp-web`，使用 Vue 实现，独立于 `hipp-admin` 与 `hipp-uni`。
- 登录支持手机号短信验证码与账号密码，请求沿用 `platform=1`：短信为 `method=1`，密码为 `method=0`；发码走 `POST /auth/sms/send`。
- 登录前需同意《用户协议》与《隐私协议》，文案与小程序内置文本一致。
- 打开站点进入登录页；已经登录则进入需求会话页。应用内不设首页菜单。左上角标识为「需求」，名称是「智臻善算」，点击标识或名称打开 `http://hipp.site/`。
- 「需求」菜单下方有「最近」。其中每一条归档记录单独显示为一个会话，并包含当前尚未归档的会话。不展示接待菜单，也不展示客户对话。
- **首版范围（强制）**：Web 用户端**暂时隐藏「商业评估」入口**（侧栏「商业」、`/business` 场景页及同类入口）；首版只交付**需求分析**。后端商业场景能力与小程序入口可保留，不要求本版下线。恢复商业入口时再打开导航与路由。
- 会话支持搜索、置顶、修改标题、删除；已结束话题支持「继续对话」。
- 同一场景下，当前会话尚未结束时也可以新开一条。没有用户或助手消息的草稿不进入「最近」；一旦有交互记录，该会话就留在对应场景的「最近」里，不必先归档。
- 有交互的会话要有概括标题，由大模型根据对话归纳，例如「Veo停车识别算法需求」。不用用户原文开头截成的一串字，也不用智能体名称。已经落成原文开头的标题，在打开列表时改写成概括标题。
- 「最近」下面有「归档」。会话可以归档；归档后离开「最近」，点开「归档」看到列表，每条显示时间、标题和 token 消耗。这与话题结束不是同一件事，归档后仍可打开该会话。
- 对话页支持历史消息、Markdown 回复、WebSocket 流式发送，流式不可用时回退为同步发送。助手回复在页面上随文字逐段出现，并带输入光标；开始生成后立刻能看到正在回复，而不是等整段结束后一次显示。回复中的深度思考不显示英文 think 标签，以中文「深度思考」呈现，默认收起，点击后展开；尚未结束时标题为「深度思考中...」，并显示已用时（如 `深度思考中...(12.7s)`），结束后保留用时（如 `深度思考 (13s)`）；历史消息无本轮计时则只显示「深度思考」。话题结束后可开启新话题。话题已结束时，原「联系人工客服」改为「联系我们」，点击后弹出关于我们，不进入人工会话。
- 需求页调用场景智能体，展示该智能体下已归档话题，并在当前会话中继续咨询。首版不提供商业页入口。
- **场景会话处理一致（强制）**：若日后恢复「商业」入口，「商业」与「需求分析」在会话生命周期上须同一套逻辑——新会话、空草稿复用、话题结束（`is_topic_closed`）、结束后开启新话题、分享/用户归档、发消息前余额校验、**话题结束扣费**。仅智能体筛选（`service_type`）与侧栏分组不同；禁止为商业另做一套扣费或结束态交互。
- 导航不含「我的」。点击左下角头像展开资料：编辑资料、修改或首次设置密码、深色模式、退出登录都在这一层完成，不再进入下一级页面。头像下方有「联系我们」，点击后弹出关于我们，展示成都智臻善算科技有限公司的名称、联系人殷先生、电话 17302868369、统一社会信用代码 91510106MAKFR2T55W、地址（成都市金牛区光荣西路 67 号 1 栋 4 楼 517 号）和备案号蜀ICP备2024076719号-1。左上角品牌与登录页品牌文案不跳转公司首页。
- 接口鉴权使用登录返回的 `token_type` 与 `access_token`；密钥与 Dify 地址不下发到浏览器。

## 非功能性要求

- 界面按桌面阅读场景设计，主色与字号层级稳定，支持浅色与深色。
- 导航、会话操作和资料入口使用统一的线性图标；主按钮与次按钮样式可区分。不改变登录、会话、归档、资料和联系我们的操作路径。
- 没有自选头像时，侧栏和资料层显示站内默认头像，不使用外部占位图。
- 开发时通过本地代理访问 `hipp-api`（默认 `127.0.0.1:46000`），浏览器不直连密钥。
- 未登录访问需登录的页面或站点根路径时进入登录页，并在登录后回到原目标页；没有目标页时进入需求会话页。

3. 话题结束后「联系我们」弹出关于我们。点「需求」或「商业」时，另一侧的最近会话清单收起。
4. 未结束也可新开会话；有交互记录的会话留在「最近」。助手回复在页面上逐字出现。
5. 会话标题由大模型概括，不再截取用户原文开头。「最近」下增加「归档」，归档列表显示时间、标题和 token 消耗。
6. 助手回复中的深度思考以中文标题展示，默认收起，点击后展开。
7. 美化图标、按钮和整体样式。没有自选头像时，侧栏和资料层显示姓氏圆印，不再使用外部占位图。登录、会话、归档、资料和联系我们的操作路径不变。
8. 明确「商业」与「需求分析」会话处理逻辑一致（结束扣费、分享/归档、新话题等同路径）。
9. 对话多模态：附件上传 OSS、随消息转发 Dify；语音转写填入输入框。见 `【对话】多模态附件与语音输入.md`。
10. Web 首版隐藏「商业评估」入口，只保留需求分析侧栏与场景页；访问 `/business` 重定向到需求页。
11. 深度思考标题显示用时（进行中与结束后），历史无计时则不显示秒数。

## 问题

1. 助手「正在回复」与用户「发送中」叠显：乐观占位出现即标已发送，二者不同时展示。见 `hipp-or/doc/91-qa/【Web对话】回复已返回时用户消息仍显示发送中.md`。
2. 深度思考较长时回复被判失败：浏览器 90 秒总超时掐断后，又用 120 秒同步转发重试并盖掉正文。见 `hipp-or/doc/91-qa/【Web对话】深度思考回复被90秒超时掐断.md`。
3. 附件上传成功但发送失败被盖成「发送失败」：上传不校验余额，发送会校验；前端吞掉「余额不足」等业务错误。见 `hipp-or/doc/91-qa/【Web对话】附件上传成功但消息显示发送失败.md`。
