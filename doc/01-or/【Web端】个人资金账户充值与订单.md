# 背景

需求分析 Web 用户端（`hipp-web`）已接入 hipp-manager 做登录与在线校验，但账户内没有余额、充值与订单入口。充值与账本能力已在 hipp-manager 落地，or 不应再自建支付与资金表。用户需要在 or 内完成充值与订单查询；需求分析与商业评估的每次会话咨询（规则相同）按固定金额从共享余额扣费。

# 目标

1. 在 or 用户端提供个人资金账户页面，可查看余额、发起充值、查询充值订单与流水。
2. 充值、支付、入账与订单数据一律走 hipp-manager API，or 后端仅透传，不落本地资金账本。
3. 每次会话咨询从共享余额扣减；金额以管理端配置为准（全局默认 0.10 元，可按用户覆盖，见 `【管理后台】会话咨询费用配置.md`）。
4. 在 or 内可查询个人「本产品」账本：充值订单与交易流水默认仅展示 `product=or`；余额仍为平台共享余额。

# 要求

## 功能性要求

1. 已登录用户可在 or Web 打开资金账户页：展示余额、充值（支付渠道 + 面额/自定义金额）、充值订单列表、交易流水。
2. or 后端提供钱包代理接口，使用服务端缓存的 `manager_token` 调用 manager 的 `/api/wallet/*`；支付回调仍指向 manager，or 不接收支付通知。
3. 充值下单后支付二维码与提示须用弹窗展示，不得嵌在充值区正文流内；微信/支付宝交互与 mgr / vf 一致。
4. 资料层提供进入资金账户的入口。
5. 每次会话咨询在**话题结束**（`is_topic_closed`）时按解析后的费用经 manager S2S 扣减；**新建会话 / 进入尚未发言的空草稿前**即校验余额充足（不预扣），不足则明确提示并引导充值，避免用户写完长文后再失败；发消息时仍保留校验（余额可能中途变化）。
6. 账户页流水与充值订单默认筛选本产品 `or`。
7. 交易流水须展示业务**标题**（会话咨询对应该会话标题；充值等无会话的行用简短说明）；本产品页**不展示产品列**（已隐含为 or）。

## 非功能性要求

1. 未配置 `HIPP_MANAGER_BASE` / `HIPP_MANAGER_KEY` 或缺少 manager 令牌时，资金/扣费失败并提示重新登录或同步账户。
2. 游客 `mp_guest` 不提供充值能力，也不走余额扣费（沿用免费体验配额）。
