# 范围

- **做**：多渠道拆 Adapter；渠道下单付款后回调 OR；OR 按单生成**独特短链**；经渠道发货接口把短链交给买家；买家打开短链核销，完成 **1 次**需求分析（免登录可写会话）。
- **不做（本方案）**：阿奇索预导码作主路径；用现有 `/share` 只读链当商品；复用小程序 `mp_guest` 免费配额当付费次卡；在笔记公域硬贴外链导流。

# 架构

```text
淘宝 / 小红书 / …          hipp-or
  Channel Adapter  ──►  统一订单履约  ──►  短链权益(1次)  ──►  核销页+会话
  (验签/解析/发货回写)     (幂等 order_id)     (token 状态机)      (与渠道无关)
```

| 层 | 职责 |
|:---|:---|
| Channel Adapter | 验签、解析订单/售后、调用该平台发货或卡券接口回写短链 |
| 统一订单履约 | `channel` + `external_order_id` 幂等；SKU→权益模板；状态与售后作废 |
| 短链权益 | 一单一 token；未用/已用/作废/过期；绑定 `service_type=requirement`、次数=1 |
| 核销与会话 | `/or/a/{token}`（路径以实现为准）；临时身份；话题结束后核销；可再生成只读 share |

# 计费（MVP）

- 渠道标价在电商平台；站内对次卡会话**不扣钱包**（权益核销即完成一次咨询）。
- 登录用户钱包按次扣费（`consume_session`）路径不变，与次卡并行。
- 不在本方案强制把小红书货款 credit 进 manager；若以后要对账再加 `biz_type`。

# 小红书首渠

1. 千帆上架电子资源/数字商品（无物流）。
2. 开放平台「订单处理」类应用：订阅订单履约消息 → OR 回调 → 生成短链 → 发货/卡券接口回写。
3. 操作步骤见 `study/配置信息/小红书千帆-成都智臻善算/`。

# 其它平台

只新增 Adapter（订单事件 + 发货回写）；权益与核销核心复用。

# 实现顺序

1. OR：权益表 + 短链核销 + 免登录一次会话（可先管理台手工造单验核销）。
2. 小红书 Adapter：回调 + 发货回写 + 售后作废。
3. 淘宝等 Adapter 按需加。

# 约束

- 同一外部订单号只生成一条有效短链（消息重试幂等）。
- 密钥、AppSecret 不进本仓库明文；落 `study/配置信息/小红书千帆-成都智臻善算/重要信息.md` 占位与受控目录。
- 未用权益退款须可作废；已核销退款走人工规则。
