# 功能设计

## 分工

| 层级 | 职责 |
|:---|:---|
| hipp-manager | 余额、充值下单、微信/支付宝、入账、订单与流水真源 |
| hipp-api | `/wallet/*` 透传：鉴权后取 Redis 缓存的 `manager_token`，调用 manager `/api/wallet/*` |
| hipp-web | `/wallet` 页面：余额、充值、订单、流水；支付码 Modal |

## 后端代理（`apps/wallet`）

前缀 `/wallet`，需 `AllUserAuth`。响应包在本产品 `SuccessResponse` / `ErrorResponse` 内，`data` 为 manager 原 JSON。

| or 路径 | manager |
|:---|:---|
| `GET /wallet/balance` | `GET /api/wallet/balance` |
| `GET /wallet/presets` | `GET /api/wallet/presets` |
| `GET /wallet/pay-channels` | `GET /api/wallet/pay-channels` |
| `POST /wallet/recharge` | `POST /api/wallet/recharge` body `{ amount, channel? }` |
| `GET /wallet/recharge/orders` | `GET /api/wallet/recharge/orders` |
| `GET /wallet/recharge/{order_id}` | `GET /api/wallet/recharge/{order_id}` |
| `POST /wallet/recharge/{order_id}/dev-pay` | 同路径（仅 manager 开启 dev 时） |
| `GET /wallet/transactions` | `GET /api/wallet/transactions`（未传 `product` 时默认 `or`）；or 侧为每条流水补 `title` |
| `GET /wallet/recharge/orders` | 同上，未传 `product` 时默认 `or` |
| `GET /wallet/bills` | `GET /api/wallet/bills` |
| `GET /wallet/session-fee` | 本地 `resolve_session_fee`，不调 manager |

无令牌或 manager 401：提示重新登录。manager 业务错误原样返回文案。

`utils/hipp_manager.py`：钱包 Bearer 调用（含 query）；S2S `deduct`（`X-Manager-Key` / `HIPP_MANAGER_KEY`）。

### 流水标题 enrichment

`GET /wallet/transactions` 在透传 manager 列表后，对当前用户补字段 `title`：

| 条件 | `title` |
|:---|:---|
| `ref_id` 匹配 `or_session_{id}` 且会话属于当前用户 | 该会话 `title`（空则用展示用兜底名） |
| `type=recharge` | `充值`（有渠道可拼「微信充值」等，首期固定「充值」即可） |
| `type=refund` | `退费` 或 `remark` 前 40 字 |
| 其它 | `remark` 截断，再空则为 `—` |

不向 manager 写标题；不在流水表落本地副本。

## 前端（`hipp-web`）

| 路径 | 说明 |
|:---|:---|
| `/wallet` | 需登录 + shell；窄栏余额/充值，下方订单与流水 |

- 资料层增加「账户余额」行，跳转 `/wallet` 并收起资料层。
- 充值 UI：支付渠道大卡片 → 面额两列 → 金额输入 + 充值；内容列 `max-width: 480px`。
- 下单成功后 Modal 展示二维码（`code_url` / `pay_url`），轮询订单至 `paid` 后关弹窗并刷新余额。
- 说明文案：每次会话咨询 ¥{动态解析金额}；流水/订单区注明本产品相关记录。
- 流水与充值订单请求默认 `product=or`。
- 交易流水列：时间、类型、**标题**、金额、余额；**不展示产品列**。

## 会话费用配置

管理端配置见 `hipp-or/doc/02-dr/05 系统管理/会话咨询费用配置设计.md`。用户侧 `GET /wallet/session-fee` 返回解析后金额。

## 会话扣费

- 时机：话题结束时扣费；**创建 dify 会话前**与**进入未发言空草稿前**校验余额（不预扣）；发消息前再校验一次；已结束未扣费打开详情时补扣。
- `amount`=`resolve_session_fee`；为 0 则跳过扣费并将 `fee_charged=1`。
- `product=or`，`biz_type=consume_session`，`ref_id=or_session_{id}`，`phone`=用户手机号。
- 成功：`fee_charged=1`；余额不足则拒绝建会话/进入空草稿/发送；结束扣费失败不回滚归档。
- 余额不足：业务码 **`46005`** + 提示充值文案；Web 按码跳转 `/wallet`。无法校验余额或未绑手机：**`46006`**。码表见 `hipp-or/doc/02-dr/04 小程序对话/mp_chat业务错误码.md`。
- 接口：`POST /mp/chat/sessions` 创建前调用 `assert_user_session_fee_affordable`；`GET /mp/chat/session-fee-precheck` 供前端在复用空草稿、「新会话」清空本地草稿前预检（与建会话同一套码）。
- 游客、人工客服会话：不扣余额。

# 约束与边界

- or 不建充值表、不接支付回调。
- 不在前端直连 manager（避免 `/or/api` 与站点根 `/api` 混淆）；一律经本产品 `/wallet` 或服务端 S2S。
- 不做会员档位；共享余额不拆 or 子账户。
